1. Optimización y performance web

El equipo reporta que los banners de campaña en la home se ven borrosos en pantallas grandes (monitores de escritorio y TV), aunque en móvil se ven nítidos. Las imágenes se sirven desde Cloudinary con una transformación fija en la URL: c_fit,w_1200.

a) Explica a qué se debe este problema y por qué ocurre solo en pantallas grandes.

b) Propón al menos dos soluciones concretas para corregirlo, considerando que las imágenes se insertan desde un CMS propio sin acceso a JavaScript.

c) Además de este caso, menciona 4 medidas generales que aplicarías para mejorar el performance (PageSpeed/Lighthouse) de un sitio de contenido con muchas imágenes y componentes visuales (banners, cards), sin depender de frameworks de JS.

Respuestas

a) Causa del problema

El parametro c_fit, w_1200 va aentregar siempre una imagen de tamaño 1200, el problema en general es que si la resolucion o tamaño del monitor es mayor a 1200 el navegado va a redimensionar esta imagen ocasionando un desenfoque o perdida de informacion en la imagen.

En dispositivos móviles la imagen tiende a reducirse, causando tambien perdida de información en la imagen. Esto no es tan optimo cuando esta imágen contiene texto.

b) Soluciones

Podemos usar srcset + sizes donde se pueden configurar multiples transformaciones.

Ejemplo:
<img src="https://res.cloudinary.com/demo/image/upload/c_fit,w_1200,f_auto,q_auto/banner.jpg" srcset=" https://res.cloudinary.com/demo/image/upload/c_fit,w_800,f_auto,q_auto/banner.jpg 800w, https://res.cloudinary.com/demo/image/upload/c_fit,w_1200,f_auto,q_auto/banner.jpg 1200w, https://res.cloudinary.com/demo/image/upload/c_fit,w_1800,f_auto,q_auto/banner.jpg 1800w, https://res.cloudinary.com/demo/image/upload/c_fit,w_2400,f_auto,q_auto/banner.jpg 2400w" sizes="100vw" alt="Banner campaña" />

Usando esto, podemos hacer el navegador use la imagen correcta dependiendo del tamaño del viewport.

Otra de las soluciones para este problema sería desde el mediaQuery definiendo el tamaño de la imagen que renderiza de acuerdo al viewport

c) Mejoras en el performance

  1. Formato y compresión automática: podemos usar f_auto,q_auto, para que de esta manera el navegador nos sirva imágenes WebP/AVIF segun lo soporte cada navegador en vez de JPEG/PNG.
  2. Lazy load: podemos agregar atributos a img como loading="lazy" a todos lo elementos fuera de la vista inicial y fetchpriority="high" para banners principales o elementos de primera vista.
  3. Definición de estilos: Declarar siemte el ancho y alto de las imagenes en css con un aspect-ratio, para que el navegador reserve un espacio antes que cargen los recursos.
  4. Pre load: <link rel="preconnect"> prar el dominio de Cloudinary/CDN y <link rel="preload" as="image"> para uso del banner principal.

6. SEO técnico y medición

  • a) Explica qué es el archivo hreflang y para qué se usa en un sitio con versiones por país (por ejemplo, seis dominios regionales en Centroamérica). ¿Qué problema de SEO evita?
  • b) Explica qué es el sitemap.xml, quién suele generarlo en un proyecto con backend propio (Desarrollo), y cuál es tu rol como Webmaster para validar que esté correctamente indexado.
  • c) ¿Qué herramienta usarías para verificar si una URL nueva fue indexada correctamente por Google, y qué pasos seguirías si detectas que no lo fue?
  • d) ¿Qué diferencia hay entre un problema de indexación y un problema de performance (Core Web Vitals)? Da un ejemplo de cómo detectarías cada uno.

Respuestas

a).

El atributo hreflang indica a los motores de busqueda que version o idioma de una página se debe mostrar segun su región o país

Cada version puede tener el mismo contenido, pero adaptado a su mercado

Evita los siguiente problemas SEO

  • Evita que los google identifique todas sus versiones como contenifo duplicado
  • Evita que usuarios vena contenido que no pertenece a su región o país
  • Mejora el UX al mostrar la versión relevante de su país

b).

El setemap.xml es un archivo XML, el cual contine una lista de urls que pertenecesn al sitio web y son usadas para la indexación del contenio o de las páginas en los motores de búsqueda. Este archivo lo genera normalmente el equipo de desarrollo.

En cuanto al roll ejercido por el web master, se encuentra:

  • Verificar que el sitemap.xml exista y se pueda acceder a el.
  • Confirmar que las URL mas relevantes se encuentren incluidad
  • Cargarlo en google Search Console
  • Revisar que se procese sin errores
  • Comprobar que las URLS se estén indexando correctamente

c).

La herramienta que se usa para verificar dicha indexación es Google Seach Console.

Para verificar la indexación, verificaría que me responda con HTTP 200 Ok, confirmaría que la etiqueta no tenga noindex, verificar que no tenga bloqueos en robots.txt, verificar si esta incluida en el sitemap.xml, solicitar indexación en google search console y finalmente esperar para verificar su estado de nuevo.

d).

La principal diferencia entre problemas de indexación y uno de performance, es que la página o contenido no se está mostrando en motores de busqueda, el cual requiere revisión desde el sitemap, ejecutando los pasos del punto anterior, para corregirlos.

En cambio, un problema de performance, puede influir en los tiempos de carga del sitio web, el cual, se entra a corregir desde la implementación del código hasta la optimización de imágenes.

Para poder hacerle seguimiento a esto, podemos usar herramientas como: PageSpeed Insights, Core Web Vitals en google search console y lighthouse.
